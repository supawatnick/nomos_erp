# API and Audit Contract

Status: PASS — Phase 1–6 transport/audit conventions.

Base path: /api/v1. OpenAPI generated by FastAPI is the machine-readable contract.

## Trusted request context
Protected use cases receive server-resolved:
- request_id UUID (accept safe client correlation only as correlation input; server owns canonical request id)
- actor_user_id
- tenant_id selected from authenticated membership
- tenant_user_id
- effective permissions and future resource scopes
- channel: WEB|API|LINE|WORKER
- locale/timezone for presentation
Never trust tenant_id, permissions, actor ID or channel from a business request body.

## Headers
Request:
- Idempotency-Key: REQUIRED for stock-changing command endpoints; opaque <=200 chars.
- X-Correlation-ID: optional safe correlation string; server still creates/returns canonical request_id.
- Accept-Language: presentation hint only.
Tenant selection is represented by authenticated server-managed context/session; if an API tenant selector is later exposed, it is validated against membership before context creation.

Response:
- X-Request-ID: canonical request id.
Do not expose infrastructure topology or internal exception details.

## Success envelope
Single resource/command:
{"data": {...}, "meta": {"request_id": "..."}}

List:
{"data": [...], "meta": {"request_id":"...","next_cursor":"..."}}

Commands return the durable resource/transaction identity and state. Idempotent replay returns the same semantic result.

## Errors
{"error":{"code":"STABLE_CODE","message":"localized safe message","details":{},"request_id":"..."}}

Baseline HTTP mapping:
- AUTHENTICATION_REQUIRED 401
- SESSION_EXPIRED 401
- PERMISSION_DENIED 403
- RESOURCE_NOT_FOUND 404
- VALIDATION_FAILED 422
- CONFLICT 409
- IDEMPOTENCY_CONFLICT 409
- CONCURRENCY_CONFLICT 409
- INSUFFICIENT_STOCK 409
- INVALID_DOCUMENT_STATE 409
- APPROVAL_REQUIRED 409
- APPROVAL_STALE 409
- DUPLICATE_RESOURCE 409
- RATE_LIMITED 429
- INTEGRATION_UNAVAILABLE 503
- INTERNAL_ERROR 500

Cross-tenant guessed object lookup should normally map to RESOURCE_NOT_FOUND to avoid existence disclosure.

## Pagination/filter/sort
Default list limit 50; maximum 200 unless endpoint documents a lower cap.
Cursor is opaque, signed or otherwise tamper-resistant, and binds to stable sort/filter context.
Every paginated query has deterministic tie-breaker (normally id).
Approved filters are endpoint-specific query parameters. No raw SQL-like filter syntax.
Sort is allowlisted. Default sort is documented per resource.
Search strings are bounded/normalized; wildcard behavior is endpoint documented.

## Mutation semantics
POST command endpoints for inventory receive/issue/transfer/adjust/opening/reversal.
PATCH for mutable master-resource partial updates where state-machine semantics are not bypassed.
DELETE is not used to erase referenced business history; archive/deactivate commands or PATCH state are used.
Stock commands require Idempotency-Key and follow INVENTORY-EXECUTION.md.
State transitions are dedicated commands/use cases, never arbitrary status PATCH.

## Decimal/time representation
Quantities/money are JSON strings in API contracts when precision matters, e.g. "12.50000000".
Timestamps are RFC3339 with timezone/UTC. Business date is YYYY-MM-DD.
Server parses exact Decimal and rejects excess precision according to unit/domain rules.

## Concurrency
Stock uses pessimistic row locking as specified.
Mutable master records SHOULD expose updated_at or version/ETag-style concurrency guard before broad multi-user editing. Silent last-write-wins is not allowed for high-risk configuration.

## Audit taxonomy
Audit is append-oriented and written in the same transaction as critical business state where possible.

Action naming: <domain>.<resource>.<verb>, stable lowercase dotted identifiers.

Required Phase 1–6 actions include:
- auth.session.created
- auth.session.revoked
- tenant.settings.updated
- organization.legal_entity.created|updated|archived
- organization.branch.created|updated|archived
- identity.tenant_user.invited|updated|disabled
- identity.role.created|updated|assigned|unassigned
- catalog.product.created|updated|archived
- catalog.category.created|updated|archived
- catalog.unit.created|updated
- warehouse.warehouse.created|updated|archived
- warehouse.location.created|updated|archived
- inventory.transaction.posted
- inventory.transaction.reversed
- inventory.stock_count.created|counted|reviewed|posted
- inventory.reorder_rule.created|updated|disabled
- import.batch.created|validated|committed|failed

## Audit payload rules
Required columns are defined in ERD. metadata may include safe:
- reason/reference
- changed field names and selected before/after values
- document/transaction number
- permission/approval context
- idempotency key hash/reference, never raw secret material
- import summary
Do NOT log password/session tokens, credentials, raw authorization headers, secret integration payloads or unnecessary PII.
For permission changes, capture before/after permission codes.
For stock posting, audit transaction ID/number/type and summarized line count/locations; authoritative quantities remain in ledger.

## Audit result
Committed critical mutations record SUCCESS. Security-relevant denied attempts may be recorded outside the failed business transaction through a safe security audit path, without leaking cross-tenant object details. Do not create misleading SUCCESS audit rows for rolled-back operations.

## Request-to-audit correlation
Every critical audit row carries request_id. Background jobs also carry a correlation/request identifier and channel WORKER. Outbox events carry aggregate identity and are created atomically with business effects.

## API exit tests
- request_id returned on success/error;
- tenant context cannot be overridden by body;
- stock endpoint without idempotency key rejects;
- replay/conflict semantics match Inventory contract;
- unsupported sort/filter rejects safely;
- cursor cannot be reused under incompatible query context;
- exact decimal round-trip;
- stable error mapping;
- direct API permission denial independent of UI;
- committed critical mutation has correlated audit row;
- rollback has no false SUCCESS audit/outbox;
- audit metadata redacts secrets.
