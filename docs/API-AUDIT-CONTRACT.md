# API and Audit Contract

Status: APPROVED — implemented Phase 1–6 transport/audit baseline plus four-core extension contract.

Base path: /api/v1. OpenAPI generated by FastAPI is machine-readable contract.

## Trusted request context
Protected use cases receive server-resolved request_id, actor_user_id, tenant_id, tenant_user_id, effective permissions/scopes, channel and locale/timezone. Business requests never supply trusted tenant, actor, permission or channel identity.

The context model must support future legal_entity_ids, branch_ids and warehouse_ids without trusting client scope. Finance operations are legal-entity scoped.

## Headers
- Idempotency-Key: REQUIRED for stock-changing commands and later for retriable cross-core/financial posting commands.
- X-Correlation-ID: optional safe correlation input; server owns canonical X-Request-ID.
- Accept-Language: presentation hint only.
Tenant selection is validated against authenticated membership.

## Envelopes
Single: {"data": {...}, "meta": {"request_id": "..."}}
List: {"data": [...], "meta": {"request_id":"...","next_cursor":"..."}}
Commands return durable identity/state. Idempotent replay returns same semantic result.

## Pagination/filter/sort
Default limit 50/max 200 unless stricter endpoint limit. Cursor is opaque/tamper-resistant and binds stable sort/filter context. Sort/filter are allowlisted; search bounded; deterministic tie-breaker normally id.

## Mutation semantics
- PATCH only mutable masters/non-state-machine fields.
- State transitions use dedicated commands/use cases.
- DELETE never erases referenced business history.
- Stock commands require idempotency.
- QT send/accept, SO confirm/cancel, PO approval/receipt, invoice/journal/payment posting/reversal use explicit commands.
- Retriable cross-core effects carry stable idempotency identity.
- Material document edits use version/concurrency guard; silent last-write-wins is forbidden for approved/sent/financially material documents.

## Decimal, currency and time
Precise quantity/money/rate values serialize as decimal strings. Currency is explicit ISO-4217. Foreign-currency financial contracts preserve transaction amount, exchange rate/value date/source and base amount. Timestamps are RFC3339; business date is YYYY-MM-DD.

## Cross-core contract envelope
A durable cross-core command/posting fact contains:
- tenant_id (trusted/server-bound)
- legal_entity_id where applicable
- source_module/source_type/source_id/source_number
- source_version where mutable source state matters
- effective/business date
- request_id/correlation identity
- idempotency identity
- exact quantities with unit/base quantity where physical
- exact amounts with currency/rate/tax context where financial

Receiver validates ownership/state. A source module never marks an effect complete solely because it attempted delivery.

## Audit metadata
Safe metadata may include reason/reference, changed field names/selected before-after values, document number/version, permission/approval context, hashed idempotency reference and summaries. Never log passwords, session tokens, credentials, authorization headers, secrets, unnecessary PII, bank secrets or full sensitive payment payloads.

Commercial transition audit preserves source/target document IDs and revision where relevant. Financial posting audit preserves journal/source IDs and balanced totals/currency summary; authoritative lines remain in financial tables.

## Audit result/correlation
SUCCESS only for committed critical mutations. Rollback cannot leave false success audit/outbox. Security denial may use separate safe security audit. Every critical audit carries request_id; worker activity carries correlation and channel WORKER. Outbox is created atomically with source effect.

## Exit tests
- request_id success/error;
- body cannot override tenant/actor/scope;
- idempotency required/replay/conflict for eligible commands;
- cursor/filter/sort safety;
- exact decimal/currency round-trip;
- direct API permission denial;
- committed critical mutation correlated audit/outbox;
- rollback no false success;
- secret redaction;
- later: cross-core source ownership/version/idempotency;
- later: QT/SO/PO lifecycle audit;
- later: financial source-posting uniqueness, closed-period rejection and balanced journal audit.
